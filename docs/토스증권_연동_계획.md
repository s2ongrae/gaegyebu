# 토스증권 Open API 연동 계획 (노트북 · Claude Code)

> **진행 상태(2026-10-25)**: 0단계(실제 키로 연결 확인)만 남고, 1~3단계 코드와 테스트는 만들어져 있어요.
> - 동기화 도구 `tools/toss-sync` (조회 전용) · 서버 `saveStockSnapshot`/`loadStockSnapshot` · 앱 주식 탭 "토스증권 보유 현황" + 주식계좌/원금 반영 버튼
> - 실제 토스 응답으로는 아직 시험하지 못했어요(가짜 서버로만). `npm run check` 결과가 토스 앱과 다르면 `tools/toss-sync/toss.js`의 `buildSnapshot`만 고치면 돼요.


> 이 파일을 저장소의 `docs/토스증권_연동_계획.md`로 넣고, Claude Code에 "이 계획대로 0단계부터 진행해 줘"라고 말하면 됩니다.
> **비밀값(client_secret, 서버 키)은 이 파일에도, 저장소에도 절대 넣지 않습니다.**

## 1. 확인된 사실 (2026-10 기준, 공개 자료)
- 토스증권 계좌가 있는 사람만 Open API 키를 발급받을 수 있다(공식 소개 페이지).
- 발급 위치: 토스증권 웹(WTS, tossinvest.com) → 설정 → Open API에서 `client_id` / `client_secret` 발급. 승인 대기 없음.
- **허용 IP 등록 필수**: 등록 안 된 IP에서 부르면 키가 맞아도 403으로 차단된다.
- 인증: OAuth 2.0 Client Credentials. `POST https://openapi.tossinvest.com/oauth2/token` → Bearer 토큰.
- 계좌·자산·주문 API는 `X-Tossinvest-Account`(accountSeq) 헤더 필요. accountSeq는 계좌 목록 조회로 얻는다.
- 기능 묶음: 인증 / 시세·종목·시장 정보 / 계좌·자산(보유 주식, 주문 가능 금액) / 주문 생성·정정·취소 / 조건주문.
- 호출 한도가 있다(클라이언트·API 그룹별 초당 제한, 계좌 목록은 특히 빡빡하다는 자료 있음) → 계좌 번호 등은 캐시.
- **확인 못 한 것**(0단계에서 공식 문서로 확인): 정확한 엔드포인트 경로·응답 필드, 조회 전용(읽기 권한만) 키를 만들 수 있는지, WebSocket 지원 여부(자료마다 다름), 해외주식 평가액의 통화 표기, 배당·체결 내역 제공 범위.

## 2. 왜 "노트북에서 도는 작은 프로그램"인가
| 어디서 부르나 | 가능? | 이유 |
|---|---|---|
| 폰·브라우저(가계부 앱이 직접) | ✗ | 접속할 때마다 IP가 바뀌어 허용 IP에 못 넣음. 게다가 client_secret이 브라우저에 노출됨 |
| 구글 Apps Script 서버 | ✗(사실상) | 구글 서버의 나가는 IP가 고정돼 있지 않아 허용 IP 등록이 현실적으로 어려움. 예전에 서버에 넣었던 토스 연동이 쓰이지 않은 것도 이 영향으로 추정(확인 안 됨) |
| **집 와이파이에 연결된 노트북** | ✓ | 집 공인 IP 하나만 등록하면 됨. 비밀값은 노트북에만 |
| 고정 IP 클라우드 서버 | ✓ | 가능하지만 월 비용·관리 부담. 지금은 과함 |

→ **노트북의 동기화 스크립트**가 토스에서 보유 현황을 가져와 **가계부 서버(Apps Script)에 "스냅샷"으로 저장**하고, 가계부 앱은 그 스냅샷을 보여 준다. 토스 키는 노트북 밖으로 나가지 않는다.

```
[노트북: tools/toss-sync] --(토스 키, 집 IP)--> 토스증권 Open API
          │ 보유종목·평가액 스냅샷
          └--(가계부 서버 키)--> Apps Script(가계부_데이터.json의 stockSnapshot) --> 가계부 앱(폰·PC)
```

주의: 집 인터넷의 공인 IP는 통신사 사정으로 바뀔 수 있다. 바뀌면 403이 나므로, 스크립트가 403을 받으면 "허용 IP를 다시 등록하세요(현재 IP: …)"라고 알려 주게 한다. 회사·카페 와이파이에서는 동작하지 않는 게 정상.

## 3. 보안 원칙 (Claude Code가 반드시 지킬 것)
1. 비밀값은 저장소 **밖** `../gaegyebu-data/.env`에만: `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`, `GAEGYEBU_SERVER_URL`, `GAEGYEBU_SERVER_KEY`. 코드·로그·에러 메시지·커밋에 절대 출력하지 않는다(마스킹).
2. **조회 전용**: 스크립트에는 주문·정정·취소·조건주문 호출 코드를 아예 만들지 않는다. HTTP 클라이언트는 허용 목록에 있는 GET 경로(+토큰 발급 POST)만 보낼 수 있게 막는다.
3. 토큰은 메모리(또는 `gaegyebu-data` 안 캐시)에만, 만료 전 재사용, 401이면 1회 재발급, 429면 `Retry-After`만큼 대기.
4. 가계부 서버에는 토스 키를 보내지 않는다. 보내는 건 보유 현황 숫자(스냅샷)뿐이고, 가계부 서버 키로 인증한다.
5. 테스트는 실제 토스 API를 부르지 않는 가짜 응답으로(기존 `tests/` 방식). 실제 호출은 사용자가 직접 실행할 때만.

## 4. 단계별 진행
**0단계 — 키 발급과 연결 확인(조회만)**
- 사용자: WTS → 설정 → Open API → 클라이언트 발급, 허용 IP에 노트북 공인 IP 등록(확인: 터미널 `curl ifconfig.me`). `.env` 작성.
- Claude Code: `tools/toss-sync/check.js` — 토큰 발급 → 계좌 목록 → 보유 주식을 표로 출력. **사용자가 토스 앱 화면과 숫자를 눈으로 대조**(맞아야 다음 단계).
- 이때 공식 문서로 엔드포인트·응답 필드를 확정하고, 1절의 "확인 못 한 것"을 채운다.

**1단계 — 스냅샷 저장**
- `server/Code.gs`에 `saveStockSnapshot` 액션 추가(키 필수, 크기·모양 검사, 개정번호와 별개로 `stockSnapshot` 필드만 갱신) + t32 테스트.
- 동기화 스크립트 `npm run toss`: 조회 → 스냅샷(시각, 계좌별 보유 종목: 종목명·수량·평균단가·현재가·평가금액·손익·통화) → 서버 저장.

**2단계 — 앱에 보여 주기(주식 탭)**
- 보유 종목 표(폰은 2줄 카드), 총 평가금액·손익, "마지막 업데이트 N시간 전".
- 오래된 스냅샷(예: 3일 이상)은 흐리게 + 안내.

**3단계 — 자산에 반영(사용자 확인 후)**
- 자산 탭의 `주식계좌` 이번 달 값을 스냅샷 평가금액으로 **제안**하고, 사용자가 누르면 저장(자동 덮어쓰기 X).

**4단계 — 자동 실행(선택)**
- 윈도우 작업 스케줄러로 평일 장 마감 후(예: 16:10) 실행. 노트북이 켜져 있고 집 와이파이일 때만 성공.

## 5. 기능 후보 (우선순위)
| 순위 | 기능 | 효과 |
|---|---|---|
| ★★★ | 보유 종목·평가금액·손익 자동 표시 | 지금 수동 입력하는 주식 숫자를 앱에서 바로 확인 |
| ★★★ | 월말 `주식계좌` 자산값 제안 | 매달 손으로 넣던 값 입력을 버튼 하나로 |
| ★★ | 일별 스냅샷 기록 → 평가액 추이 차트 | 기존 원금 기록(stockPrincipalHist)과 합쳐 "원금 대비 수익" 추이 |
| ★★ | 국내/해외 구분 + 환율 | 해외주식이 있으면 원화 환산 기준을 명확히 |
| ★ | 체결 내역 → 가계부 "투자" 거래 자동 제안 | 매수·매도를 가계부에 옮겨 적는 수고 감소(정확한 규칙 설계 필요) |
| ✗ | 주문·자동매매 | 가계부 목적 밖이고 위험이 큼 → 만들지 않음 |

## 6. 사용자가 정할 것
- 주식 탭에 **보여 주기만** 할지, 자산값 **제안**까지 할지(3단계).
- 자동 실행(4단계)을 할지, 필요할 때만 직접 실행할지.
- 해외주식 보유 여부(있으면 2단계에서 환율 표시 방식 결정).
